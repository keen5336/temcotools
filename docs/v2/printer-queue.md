# Physical-printer dispatch arbitration

`lib/labels/printer-queue.ts` coordinates the existing `LabelIssuance` rows using PostgreSQL transaction advisory locks and real row locks. It sends nothing to a printer and adds no models, broker, job service or device authority. The isolated pilot still denies `labels.print`; this module does not override that restriction.

Prepared jobs use the actual existing `queued` state. For one site and managed destination, an older queued job wins by `(createdAt, id)`, across requesting people, direct/relay modes and provider devices. One `dispatching` job blocks another claim. `unknown` blocks all later automatic claims until the original is explicitly reconciled through the existing authorized action. Unsupported retained states also fail closed. A duplicate claim returns the original receipt and never another send authorization.

`sent_unconfirmed` releases transport serialization while physical output remains unconfirmed; it is not printed/applied proof. `not_sent`, `cancelled`, `verified_not_printed`, `print_confirmed` and `applied` are also released states. The helper never converts a send/ACK into physical confirmation. It does not automatically replay an unknown job or select another device/printer. A revoked original requester is checked from current session/grant/membership state and only that still-queued issuance is retired as `not_sent`, with the existing authorization-ended event. A revoked provider cannot claim; its queue remains assigned until explicit reconnection or authorized cancellation.

The queue scope uses the originating warehouse, managed printer ID and exact normalized HTTP(S) endpoint. Identical normalized endpoint strings across managed printer records coordinate together (for example, host case and a redundant default port normalize). No DNS resolution, IP/hardware probing or equivalence between different paths/hostnames is inferred. Different configured endpoints are independent queue identities, **not proof that they reach distinct physical printers**. Configure a canonical managed destination for each known physical printer. An append-only hashed destination reservation also lets an unknown/in-flight result retain its original known endpoint scope after a later managed endpoint edit. Older dispatches without that reservation remain associated with their managed printer ID; a historical endpoint changed before this package cannot be reconstructed without retained evidence. The helper stores no endpoint credentials, creates no network request and does not return a sibling requester's content. Managed printer discovery is bounded to 500 records per site; larger inventories fail closed for explicit review.

Integrated at these existing transaction seams:

1. At the **start** of `claimLabelDispatch`, before its old `lockIssuance`, call `gatePrinterQueueDispatch(tx, principal, { issuanceId, deviceId, deviceToken })`. It verifies current device token/session/site/permission and original requester authority, acquires printer locks before the issuance row lock and returns `ready`, `blocked` or `existing`. `ready` includes the locked native row, actual device and current requester. A queue-ready result alone is not dispatch permission: retain the existing publication, approved-template, unit-context/reprint and active-printer checks. Then create the report token, change that same row from `queued` to `dispatching`, and append the native claim event **in the same transaction**. Send only after commit. Do not call the helper in an earlier transaction and later reuse its decision.
2. At the start of `reportLabelDelivery`, after the existing device check but before its issuance row lock, use `lockPrinterQueueSettlement(tx, principal, issuanceId)`. Preserve the exact original device/report-token/fingerprint validation and native result update. This hook serializes settlement with other claims; it does not authorize a result or manufacture a device report.
3. In authorized cancel/reconcile writers, replace their initial issuance row lock with `lockPrinterQueueSettlement` and retain the existing actor/`labels.manage` and evidence checks. Always use printer-before-issuance lock order. Explicit reconciliation clears an uncertain queue only by updating the retained original outcome; it does not resend that job.

The ready result is internal server data and contains native rows; expose only the established public receipt after normal checks. Blocked responses contain a bounded reason and the target issuance receipt, without another requester's ZPL or identity. Existing actor/session/client/device bindings remain unchanged. The helper writes a reservation event containing the real requester and device-owner attribution and a hashed queue key; this is queue metadata, not physical-output evidence. `LabelIssuance` has no run/step columns, so this package invents no run identity. Existing attributed workflow events remain untouched. A workflow caller may separately bind an actual checked run/step when preparing an issuance through the coordinator's orchestration seam.

`scripts/printer-queue.integration.test.ts` runs only against the exact disposable `temcotools_v2_warehouse_scope_test` database at `127.0.0.1:55439`. Fixtures use synthetic people, sessions, approved labels and `fakeprinter.invalid` destinations. They exercise real native preparation/device/report services plus the queue gate and native issuance state transition in one PostgreSQL writer transaction. Concurrent claims demonstrate one in-flight job, FIFO across providers/requesters, independent unrelated queues, alias handling, unknown no-replay, explicit reconciliation, current requester/provider revocation, site/token denial and transaction rollback. The test process temporarily permits only its local synthetic preparation/claims; no HTTP printer send occurs. Coordinator integrated native claim/report/cancel/reconcile. The additional actual-writer FIFO/ACK/unknown/reconcile scenario passed with the full10/10 PostgreSQL suite (`20261103-145503-build-90142`). Actual-device/physical printer behavior and deployment qualification remain separate; pilot printing stays disabled.
