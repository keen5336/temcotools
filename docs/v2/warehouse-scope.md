# Warehouse scope and platform authority

November 3, 2026 implementation. Explicit `User.isPlatformAdmin` supplies platform authority. The additive migration marks only the existing active `adam` legacy-admin account; other old admin/manager labels become initial-warehouse memberships. Password envelopes, MFA keys/factors/recovery, session identity and grant credentials are unchanged. Platform promotion is a separately checked current platform action; ordinary local bundles cannot grant it. Last enrolled platform-administrator and factor recovery guards remain server enforced.

`WarehouseSite`, active memberships and multiple capability bundles supply durable business scope. Local managers edit their site's memberships/roles/configuration within their current delegation. They cannot disable a person's global identity, edit platform templates, change another site or manufacture platform permissions. The same services are exposed as `sites.*` application actions through UI and MCP. Sensitive membership/configuration/publication changes require current password/authenticator confirmation. Account security remains available without a warehouse membership.

Every operational model uses a required `siteId`. PostgreSQL forces row policies on the 70 current operational tables. The central Prisma client assumes the non-superuser/non-bypass `temco_runtime` role for each short query/transaction, including raw SQL and global-model relation includes. The row policy independently checks the active site, current user/auth generation, issuing session/idle expiry and active membership or explicit platform flag. An app connection using an owner DSN must still assume the restricted role; direct maintenance clients are privileged and remain outside UI/MCP. Runtime must never export the base client or expose raw SQL execution. Existing DB intents still commit before external network effects; no outer request transaction spans a relay/print call.

Cross-site foreign-key links and updates to a row's site are rejected. Composite site/purpose keys permit independent label workflows and versions, printer/template names and dispatch day/scope. Physical-unit/LPN identities retain global uniqueness: another site's hidden unit is never silently duplicated or merged. **A controlled unit-custody transfer/history view is not implemented yet.** Such a transfer must preserve stable identity and each site's private history, rather than changing site IDs or revealing another site's source rows.

The mobile selector lists entitled active sites, and appears for multi-site users or an unselected sole membership. New sign-ins select an available membership. New documents use the selected site; existing documents pin API and Next RSC navigation, downloads and queued observations to their originating site. MCP grants and workflow runs retain their original site. Switching the UI does not retarget a grant/run. Old queued observations without a site are initial-warehouse work only. Server membership checks treat the requested header/query as selection, never authority.

Managed files retain the initial warehouse's existing root. Other warehouses use a reserved `.temco-sites/<hash>` namespace inside the same persistent volume; file/path/list controls cannot navigate it from another site's root. Private source samples retain person and site scope. Existing initial-site command/file receipt hashes remain readable so a retry cannot create a new uncertain operation merely because scope was introduced.

Verification uses disposable local PostgreSQL, actual restricted-role ORM/raw/nested/bulk queries, cross-site links, local manager delegation/CAS, immediate membership/session revocation and separate site labels. The 31→34 upgrade rehearsal compares synthetic credential/factor/session/grant values before/after; only the intended new authority/site metadata is added. This is software qualification, not a claim that actual warehouse mappings or physical-device behavior are qualified.
